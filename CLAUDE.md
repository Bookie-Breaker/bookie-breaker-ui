# bookie-breaker-ui

## Service Purpose

TypeScript/SvelteKit web dashboard for visualizing edges, predictions, line movement, simulation distributions, and paper trading performance, with Redis-driven live updates and a streaming LLM analyst chat sidebar.

## Language & Conventions

- **Language:** TypeScript (strict mode)
- **Framework:** SvelteKit 2 (adapter-node), Svelte 5 runes, Vite, Tailwind v4 + Skeleton v4, echarts
- **Project layout:** `src/routes/` for pages, `src/lib/` for shared code
- **Naming:** `kebab-case.ts` files, `PascalCase.svelte` components, `camelCase` variables
- **Package manager:** pnpm
- **Testing:** Vitest (unit + integration with msw), Playwright (e2e against `tests/e2e/stub-server.mjs`)

## Architecture Notes

- All backend access is server-side: `+page.server.ts` loads + an **allowlist** of `/api/*` proxy routes (`src/lib/server/`). Never call services from the browser and never add a catch-all proxy.
- `src/lib/api/gen/` is generated by `pnpm gen:api` from `../bookie-breaker-docs/api-contracts/openapi/` and committed; `src/lib/api/envelope.ts` holds friendly aliases.
- Live updates: `src/lib/server/event-bridge.ts` (one shared Redis subscriber) → `GET /api/events` (SSE) → `src/lib/stores/live-events.svelte.ts` (debounced `invalidate("app:*")`). Pages declare `depends("app:<domain>")`; event payloads are never rendered.
- Chat: `POST /api/chat` pipes the agent's `/analysis/stream` SSE through; page context (edge/game/performance) is injected via `src/lib/stores/page-context.svelte.ts` (ADR-017).
- Charts: pure option builders in `src/lib/charts/*.ts` (unit-tested against `fixtures/`), rendered by `src/lib/components/charts/Chart.svelte`; dev playground at `/dev/charts`.
- Edge units: REST speaks percentage points, Redis events speak fractions — convert only in `src/lib/utils/odds.ts`.
- Health endpoint for compose: `GET /healthz`.

## Key Files

- `src/routes/` — pages (`/`, `/edges`, `/edges/[id]`, `/slate`, `/lines`, `/performance`, `/bets`) + `/api` proxies
- `src/lib/server/` — env contract, upstream fetch, per-service wrappers, event bridge
- `src/lib/components/` — layout, charts, tables, bets, chat components
- `src/lib/stores/` — Svelte 5 rune stores (`.svelte.ts`)
- `src/instrumentation.server.ts` — OTEL bootstrap (ADR-012), env-gated
- `playwright.config.ts` — stub-backed e2e; `BB_E2E_STACK=1` gates the full-stack project

## Service-Specific Commands

```bash
task dev          # Vite dev server with HMR on port 3000
task lint         # eslint + prettier
task test         # vitest run (unit + integration)
task test:e2e     # playwright test (self-contained, stub backend)
task build        # Production build (adapter-node -> build/)
task check        # svelte-check
pnpm gen:api      # regenerate API types from the sibling docs repo
```

## Dependencies

- **agent** (port 8006) — Edges, slate, dashboard, alerts, streaming analysis
- **bookie-emulator** (port 8005) — Bets, performance, calibration, bankroll history
- **lines-service** (port 8001) — Current lines and movement
- **statistics-service** (port 8002) — Game schedules and stats
- **simulation-engine** (port 8003) / **prediction-engine** (port 8004) — Distributions, predictions
- **Redis** — pub/sub for the live-updates SSE bridge

## Environment Variables

See `.env.example`. All server-side (`$env/dynamic/private`): `AGENT_URL`, `BOOKIE_EMULATOR_URL`, `LINES_SERVICE_URL`, `STATISTICS_SERVICE_URL`, `SIMULATION_ENGINE_URL`, `PREDICTION_ENGINE_URL`, `REDIS_URL`, `ORIGIN`, `PORT`, optional `OTEL_EXPORTER_OTLP_ENDPOINT`.
